# Migração Umbra → Aroli

Iniciada em 2026-09-20; validação final em 2026-09-21. Branch: `rebrand/aroli`.

## Autorização e ponto de partida

O usuário aprovou explicitamente o [storyboard Aroli](../../output/imagegen/aroli-study-01/storyboard.png) e pediu a migração completa do branding em uma branch nova. A paleta permanece. O [prompt original](../../output/imagegen/aroli-study-01/PROMPT.md) documenta a exploração ImageGen.

O worktree tinha mudanças anteriores na fonte, Zed, laboratórios do site e JetBrains. Elas foram preservadas no commit **71464ec** (`chore: preserve existing font, playground and theme work before Aroli migration`). A migração é posterior e separada desse ponto de base. Nenhuma alteração foi aplicada à branch main, publicada ou instalada em configurações pessoais.

O arquivo raster aprovado permanece como referência, não como original técnico do logo.

## Implementação

- **Marca:** geometry.ts compartilha BODY/PIECE; build.ts gera símbolo claro/escuro, avatar, wordmark, assinatura, prancha, provas de escala/inversão/desfoque e teste de troca de nome.
- **Aplicações:** favicon, avatar web, ícones VS Code/JetBrains/Chrome, promos Chrome, fundos NTP e wallpaper Encaixe em 3840 × 2160.
- **Site:** nomes, metadata e JSON-LD, assinatura, fonte Switzer, hero “Tudo encontra seu lugar.” e planos curvos com acomodação de 280 ms. Estado final estático para movimento reduzido; CTA funcional sem Lenis. Laboratórios, mocks, seletores, classes, testes e assets usam Aroli.
- **Fonte:** família/nomes internos/arquivos e glifo U+100000 passam para Aroli; build, verificação e prova real em Pango/HarfBuzz atualizados. O desenho do alfabeto do protótipo foi preservado. O WOFF2 do laboratório foi regenerado.
- **Pointer:** nome de produto, documentação, CI e catálogos migrados. Anatomia de mãos/seta, hotspots, estados e timings dos XCursor preservados e verificados.
- **Temas:** manifestos, nomes no seletor e documentação atualizados, sem alterar a paleta. Pacotes locais reconstruídos.
- **Histórico:** branding antigo, explorações e pacotes antigos ficam em branding/archive; changelogs antigos não são reescritos como se já fossem Aroli. Capturas reais anteriores permanecem identificadas como evidência da paleta.

## Switzer e reprodução

O pacote oficial contém ITF FFL 2.0 (17 Aug 2026), arquivada em [SWITZER-LICENSE.txt](../../branding/aroli/SWITZER-LICENSE.txt). Ela permite uso no site, mas restringe redistribuição do software da fonte por repositórios. Por isso:

- setup:fonts obtém diretamente o [pacote oficial](https://api.fontshare.com/v2/fonts/download/switzer), compara a licença e prepara WOFF2 variável e TTF Medium sem modificar a fonte;
- arquivos Switzer em web/app/fonts são ignorados pelo Git;
- o site usa next/font/local; depois da preparação, compila sem buscar fontes na rede;
- a assinatura e os textos das pranchas são obras gráficas em curvas, não distribuição de fonte;
- a Mono autoral e seus ícones Nerd Fonts têm créditos/licenciamento separados.

Comandos a partir da raiz:

```sh
cd fonts/aroli
bun install --frozen-lockfile
bun run build
cd ../../web
bun install --frozen-lockfile
bun run setup:fonts
bun run sync:playground
bun run typecheck
bun run test
bun run build
cd ..
bun branding/aroli/build.ts
bun scripts/verify-migration.ts
make -C themes/cursor/aroli check preview
bun scripts/package-chrome.ts
cd themes/jetbrains/aroli
bun run verify
bun run package
cd ../../vscode/aroli
bunx --bun @vscode/vsce package --no-dependencies
```

Scripts web chamam Next explicitamente com Bun. No ambiente desta migração, o build inicial isolado não concluiu os workers; a execução final fora do sandbox terminou sem desabilitar a checagem de tipos. Ferramentas locais observadas: Bun 1.4.2, Next 16.3.4 e TypeScript 5.9.3. As faixas/lockfiles de dependências existentes não foram atualizados para fazer o rebranding.

## Validação e limites

- Site: TypeScript, 14 testes e build de produção concluídos; páginas /, /_not-found e /icon.svg pré-renderizadas.
- Smoke test HTTP do servidor de produção: página com a marca Aroli, favicon, assinatura, avatar, Aroli Mono e Switzer retornaram 200 com os tipos de conteúdo esperados. Servidor temporário encerrado após a checagem.
- Temas: comparação automatizada com 71464ec confirma valores de cores/mapeamentos de VS Code, Zed, Chrome, JetBrains, Kitty e Starship preservados. IDs estáveis e caminhos dos manifestos verificados. O script exige esse commit disponível no histórico local; em clone raso, obter o histórico antes de executá-lo.
- Fonte: build, cobertura, ponto de j, larguras, ligaduras/calt e ícones verificados. Tabela GSUB presente. PNG do espécime renderizado e inspecionado, incluindo tamanhos 12/14/16/24 px.
- Cursores: 32 cursores, 234 frames, três tamanhos, aliases, alpha, margens, hotspots, timings e loop verificados pelo procedimento do módulo. Catálogo e folha dos pixels dos binários inspecionados em fundos claros/escuros.
- Branding: prancha de produção renderizada e inspecionada; coordenadas SVG verificadas contra NaN/Infinity. Monocromia, escala, desfoque e relação entre peças avaliadas internamente. O gerador serializa explicitamente comandos de contorno para evitar coordenadas inválidas observadas no serializador da biblioteca.
- Pacotes: verificação de estrutura JetBrains e integridade ZIP; VSIX gerado pelo empacotador oficial; Chrome contém manifesto e imagem atualizados.

Não foi possível realizar uma sessão de revisão visual do site: o conector de navegador disponível retornou nenhum navegador conectado. Build e testes não substituem essa revisão. Não houve instalação/teste da nova identidade dentro de IDEs, Chrome ou sessão desktop. Não houve estudo humano de lembrança em cinco segundos; a aprovação da direção pelo usuário não equivale a medição de reconhecimento/exclusividade.

## Reversão e próxima publicação

O commit 71464ec preserva o estado anterior. Para comparação segura, usar um worktree separado nesse commit; para desfazer a migração depois de integrada, reverter o commit de migração, preservando o commit de base. Não usar reset destrutivo sobre trabalho novo.

Para publicar posteriormente: revisar o site em navegador real e os temas nos aplicativos, integrar a branch, publicar os pacotes nas contas corretas e, se desejado, renomear o repositório remoto com atualização coordenada de links. Nada disso foi executado implicitamente durante esta migração.
